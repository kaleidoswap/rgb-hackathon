From zero to an RGB agent

Five steps; open the ones you need. No Docker, or short on time? Open step 4 and run the agent against the built-in mock node first.

1

Run an RGB Lightning Node

One command with the kaleido CLI, or use the desktop app.›

The kaleido CLI installs, creates and starts a node on Mutinynet with sensible defaults. Requires Docker. Prefer a UI? The desktop app runs a node for you.

curl -fsSL https://raw.githubusercontent.com/kaleidoswap/kaleido-cli/master/install.sh | sh
kaleido setup                      # create + start one node
kaleido wallet balance             # check it answers
2

Fund it

Test BTC and RGB assets from the faucets.›
  • BTC: send signet coins to your node address from the Mutinynet faucet.
  • Colorable UTXOs: create a few before receiving or issuing RGB (rln_create_utxos, or ask the agent).
  • RGB assets: claim USDT and XAUT from the KaleidoSwap RGB faucet (sign in with GitHub).
  • Lightning: buy a channel from the KaleidoSwap maker to pay and receive invoices.
3

Give an AI access with kaleido-mcp

Plug your node into Claude Code, Claude Desktop or Cursor.›

What MCP is: the Model Context Protocol is the standard way an AI app discovers and calls external tools. kaleido-mcp is a small server that the AI app starts for you; it exposes your node and the KaleidoSwap DEX as tools (rln_list_assets, rln_create_rgb_invoice, kaleidoswap_get_quote…). You don't run it yourself: you register it once, then just chat.

Claude Code
claude mcp add kaleido -e RLN_NODE_URL=http://localhost:3001 -- npx -y kaleido-mcp
Claude Desktop, Cursor or any MCP client

Add this to the client's MCP config (Claude Desktop: Settings → Developer → Edit Config), then restart it.

{
  "mcpServers": {
    "kaleido": {
      "command": "npx",
      "args": ["-y", "kaleido-mcp"],
      "env": { "RLN_NODE_URL": "http://localhost:3001" }
    }
  }
}

Check it works: ask "What's my node info?". The client shows a call to rln_get_node_info and answers with your node's pubkey and channel count. RLN_NODE_URL is wherever your node's API listens; the CLI default is shown. Want ready-made skills too? Install the Claude Code plugin.

4

Go local with KaleidoMind

The same agent, with the model running on your own machine.›

What KaleidoMind does: @kaleidorg/mind is the agent loop that replaces the cloud AI. It runs a model on-device through QVAC, connects to kaleido-mcp for tools, loads a skill (instructions that teach the model how to use an RGB node), and pauses before any tool that moves funds until you approve it. It is the engine behind the AI chat in our desktop and mobile wallets.

The rgb-agent example asks three questions in a row: balances, a 10 USDT invoice, then a 5 USDT send (only if you set RECIPIENT_INVOICE). Change the steps list in src/index.ts to ask your own.

git clone https://github.com/kaleidoswap/kaleido-mind && cd kaleido-mind
corepack enable && pnpm install && pnpm build
cd examples/rgb-agent
pnpm start:mock     # fake node, real local model (downloaded once)
pnpm start          # your node via kaleido-mcp

What you'll see in mock mode:

> Which RGB assets do I hold, and what are the balances?
  tool rln_list_assets {}
You hold 1,000 USDT and 2 XAUT.

> Create an RGB invoice so I can receive 10 USDT.
  tool rln_create_rgb_invoice {"asset":"USDT","amount":10}
Here is your invoice: rgb:~/~/~/sig/…/10/utxob:…

> Send 5 USDT to this RGB invoice: rgb:…
  tool rln_send_asset {"asset":"USDT","amount":5,"to":"rgb:…"}
  Send 5 USDT to rgb:…. Confirm? [y/N]
5

Talk to it

Example requests and what comes back.›

Works the same in an MCP client, the KaleidoMind example, or the AI chat in our wallets. Short, specific requests work best.

Which RGB assets do I hold, and what are the balances?
rln_list_assetsA list like "USDT: 100 spendable, XAUT: 0.5", each with its asset id.
Create 3 colorable UTXOs so I can receive RGB.
rln_create_utxosAsks you to confirm (it spends on-chain fees), then reports the UTXOs created.
Issue a token named Hackathon Coin, ticker HCK, supply 1,000,000.
rln_issue_assetAsks you to confirm, then returns the new asset id (rgb:…).
Create an RGB invoice to receive 10 HCK.
rln_create_rgb_invoiceAn rgb:… invoice string to share with the payer.
Quote 0.0005 BTC to USDT on KaleidoSwap.
kaleidoswap_get_quoteThe USDT you would receive, the fee and how long the quote is valid.
Pay this Lightning invoice: lntbs…
rln_pay_invoiceReads back the invoice and waits for your yes, then reports the payment status.

Which model?

  • Start with Qwen3.5 2B through QVAC. In our own informal runs it handled balances, issuance, invoices and quotes, and is fast enough for a live demo.
  • Go bigger (4B, 9B) if answers are sloppy and your machine has the memory; go smaller only for read-only questions.
  • Expect it to be slow on a laptop: tens of seconds to minutes per request.
An experiment, not a benchmark

These are notes from our own tests, not guarantees. Results change with hardware, prompts and model versions: measure on your setup. The rgb-agent example loads a Qwen3 model by default; change modelSrc to try others.

Good to know

  • Test funds only. Everything runs on Mutinynet. Never put a mainnet seed in an agent config.
  • Keep the confirmation gate on. Tools that move funds are flagged; KaleidoMind and the wallets ask before running them.
  • Colorable UTXOs first. If an RGB invoice or issuance fails, ask the agent to create UTXOs.
  • Use asset ids, not tickers. Invoices and sends take the RGB asset id; have the agent list assets first.
  • Trust tool output, not the model. Small models can invent values. Only show invoices, addresses and ids that came back from a tool call.
Stuck?

Run the agent in mock mode to tell model problems from node problems, or try a bigger model. See the AI tools docs and the 15-minute tutorial, open an issue on the repo, or find the KaleidoSwap team at the venue.

From zero to an RGB agent

Five steps. Steps 1 and 2 need Docker. No Docker, or short on time? Jump to step 4 and run the agent against the built-in mock node first.

  1. 1

    Run an RGB Lightning Node on signet

    The kaleido CLI installs, creates and starts a node on the KaleidoSwap signet (Mutinynet) with sensible defaults. Requires Docker. Prefer a UI? The desktop app runs a node for you.

    curl -fsSL https://raw.githubusercontent.com/kaleidoswap/kaleido-cli/master/install.sh | sh
kaleido setup                      # create + start one signet node
kaleido wallet balance             # node API on http://localhost:3001
  2. 2

    Fund it from the faucets

    Get signet BTC from the Mutinynet faucet, then RGB test assets (USDT, XAUT) from the KaleidoSwap RGB faucet (sign in with GitHub). Create colorable UTXOs before receiving or issuing RGB.

  3. 3

    Start kaleido-mcp

    One MCP server for the node, the DEX and payments. It defaults to signet. Plug it into Claude Desktop, Claude Code, Cursor or your own agent.

    {
  "mcpServers": {
    "kaleido": {
      "command": "npx",
      "args": ["-y", "kaleido-mcp"],
      "env": { "RLN_NODE_URL": "http://localhost:3001" }
    }
  }
}
  4. 4

    Add a local model with QVAC

    @kaleidorg/mind runs the agent loop on-device and stops before every spend until you confirm. The rgb-agent example wires a QVAC model to kaleido-mcp; start:mock uses a fake node so it works anywhere. Use a Qwen3.5 model.

    git clone https://github.com/kaleidoswap/kaleido-mind && cd kaleido-mind
corepack enable && pnpm install && pnpm build
cd examples/rgb-agent
pnpm start:mock     # fake RLN node, real local model (downloaded once)
pnpm start          # your signet node via kaleido-mcp
  5. 5

    Talk to it

    • Which RGB assets do I hold, and what are the balances?
    • Create 3 colorable UTXOs so I can receive RGB.
    • Issue a token named Hackathon Coin, ticker HCK, supply 1,000,000, precision 0.
    • Create an RGB invoice to receive 10 HCK.
    • Quote 0.0005 BTC to USDT on KaleidoSwap.

Which model to use

Use Qwen3.5 through QVAC. We ran the same seven wallet tasks on a live signet node with each size: balance, asset list, issuing a token, an RGB invoice for it, a BTC→USDT quote and a send that must stop at confirmation. Qwen3 failed the issuance every time; Qwen3.5 2B and up passed all of them. Times are per question on an Apple M4 (24 GB).

Qwen3.5 0.8B~0.5 GB · 35–230 s

Reads balances and assets, but loops on multi-step actions. Not for wallet actions.

Qwen3.5 2B · recommended~1.3 GB · 45–150 s

Passed every task, including issuance and invoices. Fastest usable size; best for live demos.

Qwen3.5 4B~2.7 GB · 105–330 s

Same results as 2B with more polished answers, about twice as slow.

Qwen3.5 9B~5.7 GB · 180–690 s

Also passes; for 16 GB+ machines when quality matters more than speed.

import { loadModel, QWEN3_5_2B_MULTIMODAL_Q4_K_M } from '@qvac/sdk';
const modelId = await loadModel({ modelSrc: QWEN3_5_2B_MULTIMODAL_Q4_K_M, modelConfig: { ctx_size: 8192, tools: true } });

All four sizes are multimodal: load the matching projector to read invoices, QR codes or receipts from images.

Our wallets

Three KaleidoSwap wallets you can use during the hackathon. The desktop app and Rate are open source (MIT): fork them and ship your feature inside a real wallet. The browser extension is in closed beta: you cannot modify it yet, but you can use it as the wallet behind your dApp.

KaleidoSwap Desktop

Open source · fork it v0.5.1 · Tauri 2 · macOS, Windows, Linux

What it is

A desktop wallet that runs its own RGB Lightning Node or connects to a remote one. Swaps with makers, DCA, limit orders, LSP channel requests, BTC and RGB deposits and withdrawals. Works on signet (Mutinynet) with a built-in maker.

QVAC inside

KaleidoMind chat: ask the wallet to check balances, create invoices, quote or swap. On first use it downloads a local runtime (@kaleidorg/mind-provider on QVAC 0.21, llama.cpp) and lets you pick a model or paste any Hugging Face GGUF link. Phone pairing is paused in this release.

Use it at the hackathon

  • As your node: the easiest way to get a funded RGB + Lightning node on signet with a UI, then point kaleido-mcp at it.
  • As a model playground: try Qwen3.5 sizes against your own node from the chat before wiring your app.
  • Fork it: add a skill or a new chat action to KaleidoMind, or a new screen for your RGB use case.
git clone https://github.com/kaleidoswap/desktop-app && cd desktop-app
pnpm install
pnpm run tauri:dev     # needs the Tauri prerequisites

Rate

Open source · fork it v0.4.0 · Expo / React Native · Android, iOS

What it is

A non-custodial, multi-protocol mobile wallet: on-chain BTC, RGB on the phone itself or through an RGB Lightning Node, Lightning, Spark, Arkade, Bark and the Flashnet AMM, in one app.

QVAC inside

An on-device assistant you can talk to. QVAC runs a Qwen3.5 model, Whisper for speech-to-text and Supertonic for text-to-speech, all on the phone. One agent handles chat and hands-free voice, with confirmation before any payment. Use a physical device: simulators can't run the models.

Use it at the hackathon

  • As a phone wallet to receive and send the RGB assets your agent creates.
  • Add a skill: drop a skills/<name>/SKILL.md (name, description, tools, triggers), run pnpm bundle-skills, and the voice assistant can use it.
  • Build a voice feature on top of the existing Whisper + TTS pipeline.
git clone https://github.com/kaleidoswap/Rate && cd Rate
# follow the README Quick Start (Expo dev build)
pnpm bundle-skills     # after adding skills/<name>/SKILL.md

KaleidoSwap Browser Extension

Closed beta · use, don't modify v0.3.0 · Chromium, Manifest V3

What it is

A browser wallet for RGB (on-chain and over Lightning), Spark, Liquid, Arkade and Bark. It injects a window.rgb provider, alongside window.webln, on HTTPS and localhost pages, so web apps can request addresses, RGB receive invoices and payments. Every call that moves funds opens a confirmation popup.

Status

The source is not public yet, so you cannot fork it during the hackathon. It ships as an invite-only beta build loaded in developer mode. It has no QVAC features today.

Use it at the hackathon

  • As the wallet for your dApp: build against the @kaleidorg/webrgb mock wallet, then test end to end with the extension on localhost.
  • Pair it with your agent: your local AI prepares the action, the extension's popup is where the user approves it.
  • Get a build: ask the KaleidoSwap team at the venue for a beta invite.

Good to know

  • Test funds only. Everything runs on signet. Never put a mainnet seed in an agent config.
  • Spends need confirmation. Tools that move funds are flagged; KaleidoMind asks your app before running them. Keep that gate on in demos.
  • Colorable UTXOs first. Receiving or issuing RGB on-chain needs free UTXOs. Ask the agent to create them if an invoice or issuance fails.
  • Use asset ids, not tickers. Invoices and sends take the RGB asset id. Have the agent list assets first to look it up.
  • Keep answers short. Local models think before acting; short, specific requests are much faster than open questions.
  • Check what the model returns. Small local models can invent values. Only show invoices, addresses and ids that came back from a tool call.
Stuck?

Run the agent in mock mode to separate model problems from node problems, or try a bigger Qwen3.5. Check the AI tools docs and the MCP server guide, open an issue on the repo, or find the KaleidoSwap team at the venue.

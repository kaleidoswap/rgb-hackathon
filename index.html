RGB libraries

SDK docs ↗

Build your own RGB wallet or app. Pick by where your keys live: in your app (rgb-lib), in a node (RGB Lightning Node), or in the user's wallet (webrgb).

Wallet core

Hold and move RGB assets yourself.

rgb-lib

Rust · bindings

The library behind most RGB wallets. Issue, receive and send RGB assets on-chain without dealing with Bitcoin or RGB internals. Works offline and watch-only.

Use it for an on-chain RGB wallet inside your own app.

npm i rgb-lib              # Node.js bindings
pip install rgb-lib        # Python
GitHubNode.jsKotlin, Swift, Python, C

rgb-lib-wasm

npm · beta

rgb-lib compiled for the browser: IndexedDB storage, Esplora over HTTP, encrypted backups.

Use it for an RGB wallet that runs entirely in a web page or extension.

npm i @utexo/rgb-lib-wasm
GitHub

RGB Lightning Node

Rust · Docker · REST

A Lightning node with RGB built in, controlled over a REST API. Holds RGB on-chain and in channels, pays and receives RGB invoices, runs atomic swaps.

Use it for RGB over Lightning, swaps, and as the backend for agents.

curl -fsSL https://raw.githubusercontent.com/kaleidoswap/kaleido-cli/master/install.sh | sh
kaleido setup              # create + start a node on Mutinynet

Example: an RGB agent end to end

15-minute tutorial ↗

Putting the pieces together: a node, test funds, kaleido-mcp, and a local model. Open the steps you need. No Docker? Jump to step 4 and use the mock node.

1

Get a node

The kaleido CLI, or the desktop wallet.›

Run an RGB Lightning Node with the kaleido CLI (needs Docker), or use KaleidoSwap Desktop, which runs one for you.

curl -fsSL https://raw.githubusercontent.com/kaleidoswap/kaleido-cli/master/install.sh | sh
kaleido setup                      # create + start one node
kaleido wallet balance             # check it answers
2

Fund it

BTC, colorable UTXOs, RGB assets, a channel.›
  • BTC from the Mutinynet faucet.
  • Colorable UTXOs before receiving or issuing RGB (rln_create_utxos, or ask the agent).
  • USDT and XAUT from the RGB faucet.
  • A channel from the RGB Lightning maker, to pay and receive invoices.
3

Connect an AI with kaleido-mcp

Claude Code, Claude Desktop or Cursor.›

MCP is the standard way an AI app discovers and calls tools. You register kaleido-mcp once; the AI app starts it for you and you just chat.

Claude Code
claude mcp add kaleido -e RLN_NODE_URL=http://localhost:3001 -- npx -y kaleido-mcp
Claude Desktop, Cursor or any MCP client

Add to the client's MCP config (Claude Desktop: Settings → Developer → Edit Config), then restart it.

{
  "mcpServers": {
    "kaleido": {
      "command": "npx",
      "args": ["-y", "kaleido-mcp"],
      "env": { "RLN_NODE_URL": "http://localhost:3001" }
    }
  }
}

Check it: ask "What's my node info?". You should see a call to rln_get_node_info and your node's pubkey. RLN_NODE_URL is your node's API address.

4

Go local with KaleidoMind

Same agent, model on your machine.›

The rgb-agent example runs a QVAC model, connects it to kaleido-mcp, loads the RGB node skill and asks three questions: balances, a 10 USDT invoice, then a 5 USDT send (only with RECIPIENT_INVOICE set). Edit steps in src/index.ts to ask your own.

npm create @kaleidorg/mind my-agent
cd my-agent && npm install
npm run start:mock  # fake node, Qwen3.5 2B on-device (~1.3 GB, downloaded once)
npm start           # your node via kaleido-mcp
> Which RGB assets do I hold, and what are the balances?
  tool rln_list_assets {}
You hold 1,000 USDT and 2 XAUT.

> Create an RGB invoice so I can receive 10 USDT.
  tool rln_create_rgb_invoice {"asset":"USDT","amount":10}
Here is your invoice: rgb:~/~/~/sig/…/10/utxob:…

> Send 5 USDT to this RGB invoice: rgb:…
  tool rln_send_asset {"asset":"USDT","amount":5,"to":"rgb:…"}
  Send 5 USDT to rgb:…. Confirm? [y/N]
5

Talk to it

Example requests and what comes back.›

Same in an MCP client, the KaleidoMind example, or the AI chat in our wallets. Short, specific requests work best.

Which RGB assets do I hold, and what are the balances?
rln_list_assetsA list like "USDT: 100 spendable, XAUT: 0.5", each with its asset id.
Create 3 colorable UTXOs so I can receive RGB.
rln_create_utxosAsks you to confirm (it spends on-chain fees), then reports the UTXOs created.
Issue a token named Hackathon Coin, ticker HCK, supply 1,000,000.
rln_issue_assetAsks you to confirm, then returns the new asset id (rgb:…).
Create an RGB invoice to receive 10 HCK.
rln_create_rgb_invoiceAn rgb:… invoice string to share with the payer.
Quote 0.0005 BTC to USDT on KaleidoSwap.
kaleidoswap_get_quoteThe USDT you would receive, the fee and how long the quote is valid.
Pay this Lightning invoice: lntbs…
rln_pay_invoiceReads back the invoice and waits for your yes, then reports the payment status.

Which model?

  • Start with Qwen3.5 2B through QVAC. In our own informal runs it handled balances, issuance, invoices and quotes, and is fast enough for a live demo.
  • Go bigger (4B, 9B) if answers are sloppy and your machine has the memory; go smaller only for read-only questions.
  • Expect it to be slow on a laptop: tens of seconds to minutes per request.
An experiment, not a benchmark

These are notes from our own tests, not guarantees. Results change with hardware, prompts and model versions: measure on your setup. The rgb-agent example loads a Qwen3 model by default; change modelSrc to try others.

Good to know

  • Test funds only. Everything runs on Mutinynet. Never put a mainnet seed in an agent config.
  • Keep the confirmation gate on. Tools that move funds are flagged; KaleidoMind and the wallets ask before running them.
  • Colorable UTXOs first. If an RGB invoice or issuance fails, create UTXOs.
  • One wallet, one device. Never load the same rgb-lib or node mnemonic in two places: RGB assets can be lost.
  • Use asset ids, not tickers. Invoices and sends take the RGB asset id; list assets first.
  • Trust tool output, not the model. Only show invoices, addresses and ids that came back from a tool call.
Stuck?

Run the agent in mock mode to tell model problems from node problems, or try a bigger model. Check the KaleidoSwap docs (AI tools, SDK, CLI), open an issue on the repo, or find the KaleidoSwap team at the venue.
